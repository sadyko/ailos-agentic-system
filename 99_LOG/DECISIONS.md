## 2026-07-10 — EasyMed: clinic admin can now ALSO be a doctor (ADMIN_DOCTOR_V1)
Design flaw: "is a doctor" and "permission role" were conflated. actorFromUser hard-coded isDoctor = !isAdmin && (...), so a user was admin XOR doctor, never both. Worse, the employee editor's "This employee is a doctor" toggle auto-assigned the Doctor permission role, and a DB trigger flips users.role text to match — which turned off is_admin and locked the admin out of Settings (this hit corelmed's owner: role became 'doctor', role_id=Doctor). Fix (3 SPA files):
- auth.js actorFromUser: isDoctor = role==='doctor' || is_doctor===true || specialty || license (decoupled from is_admin) — a user can be both.
- permissions.js scopedDoctorId: admins (super admin OR clinic admin) are never patient-scoped, even when also a doctor — they see all data; only pure doctors are scoped.
- employee-editor.js: the is_doctor toggle no longer reassigns the role when the user is an admin (guard on role!=='admin'), so marking an admin a doctor keeps their full access.
Data restore: set corelmed owner's role_id back to the admin role (trigger → role text 'admin'), kept is_doctor=true → now admin+doctor. applyActorPermissions already grants is_admin full access, so an admin-doctor keeps Settings AND appears in doctor lists / has the consultation workspace.
