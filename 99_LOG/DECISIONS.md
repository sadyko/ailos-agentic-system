## 2026-07-10 — EasyMed gateway CRUD route never parsed its body (CRUD_BODY_FIX)
Import still failed with "[object Object]" after SERVICES_GATEWAY_V1. Root cause: `POST /api/v1/crud/{table}` was defined `crud_insert_route(table, body, em=...)` with **`body` unannotated** → FastAPI treated it as a query param → every request 422'd (the "[object Object]" was FastAPI's validation-error array shown by gw()). This silently broke BOTH the services import AND the drug-catalog add (same route). Fix attempt `body: list` CRASHED the gateway on boot (FastAPI treats a bare `list` body as form-data → needs python-multipart, not installed → all clinics' gateway features down briefly). Correct fix: `from fastapi import Body` + `body: list = Body(...)` (forces JSON body). Gateway back up, route now parses the body (403 auth not 422), end-to-end services batch inserts 2/2 with 0 RLS rejections. Lesson: a JSON-array FastAPI body param MUST be `= Body(...)` (a bare `list` annotation → form-data → multipart crash; unannotated → query param → 422). crud_update's `body: dict` was fine (dict bare = JSON body).
