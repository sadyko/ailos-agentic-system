Roles & Employees — reference wireframe

How the clinic admin handles staff, roles and permissions. Verified against the live code (2026-07-10).

1 The mental model

A logged-in user is a users row. The app derives three flags from it, then decides access. Permissions come from the user's role; full access is a state (super/clinic admin), not a role.

is_super_admin

users.is_super_admin

Platform god-mode across all clinics. Set only by the super admin.

is_admin

role === 'admin'

Clinic owner/admin. No dedicated column — it's the role text. Bypasses the role and gets full access to their clinic.

is_doctor

is_doctor · specialty · license

A capability: doctor lists + consultation workspace. Independent of admin — a user can be both.

2 Three access levels

Every granted module carries a level, stored in roles.permissions.levels. A granted key with no explicit level defaults to editor (delete must be granted on purpose).

From login to a yes/no on any button. The order matters — admins short-circuit before the role is ever read.

7 Database — the role-sync trigger

The one behaviour that surprises everyone: assigning a role_id rewrites the users.role text to that role's name.

trg_sync_users_role_text (migration 044)

before insert or update of role_id on users:
  new.role := lower(roles.name of new.role_id)
Consequence Assign the "Doctor" role → users.role='doctor' → is_admin turns off. To keep someone admin, don't reassign their role; use the is_doctor flag for doctor capability.

RLS helpers (migrations 033 / 041)

current_user_is_admin()    -- role='admin'
current_user_company_id()
current_user_branches()
current_user_is_doctor()
current_user_id()

Writing users.role_id requires current_user_is_admin() — only the owner assigns roles (mirrored client-side).

8 Gotchas

  • Role-text sync trigger overwrites users.role from role_id — flipping the Doctor role turns off admin.
  • is_admin has no column — it's role='admin'. The clinic-admin bypass keeps owners from being locked out.
  • is_doctor must be in the user-load SELECT, or the app can't tell an admin is also a doctor.
  • Admin + doctor is supported (was hardcoded XOR before).
  • Unlisted key = editor, not admin — delete rights are explicit.
  • scopedDoctorId (data scope) ≠ selfDoctorId (self identity) — admins are null for scope but still their own doctor.
  • Head cashier = Cashier@Admin, not a named role.
  • permissions.js/auth.js are version-less imports → after edits, Ctrl+Shift+R hard refresh.
