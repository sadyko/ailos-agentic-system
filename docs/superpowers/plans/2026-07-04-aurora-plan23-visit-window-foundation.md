# Aurora Redesign — Plan 23: Visit registration 4a — window shell, visit settings bar, coverage/referral/loyalty dialogs

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`).

**Goal:** Open Slice 4 (the «Новый визит» window) with its foundation. A routed page `/registration/visit/:patientId?` («Регистрация пациентов / {name} · Новый визит»; no patientId = «Калькулятор услуг» mode with an «Добавить пациента» attach modal; inpatients get a full-page guard card instead of the window). The page carries the **visit settings bar**: Тип пациента dropdown (Амбулаторный/Экстренный «Запись даже в закрытые слоты»/Стационарный «Ведёт к истории болезни» + per-type behaviour banners), Тип визита dropdown (Первичный/Повторный), and three summary pills opening dialogs — **Покрытие** (coverage type 2×2 grid Платно/ДМС/Корпоративный/ОМС; payer list per type with contract lines; policy combobox over the patient's saved policies + «Новый полис…»; limit input; validity date range with an inversion warning; «Платно» short-circuits to a hint), **Источник** (referral category chips ×6; searchable source list; «Внешние врачи» searches the top-10 partner doctors by ID/name), **Лояльность** (4 sub-tabs: personal discount level, patient vouchers with used-state, gift certificates with balances, promo-code entry + previously applied; multi-pick with «Выбрано: N» summary) — plus the **cart pill** (count + running total + bump animation) that jumps to the appointments panel (stub in this plan). The cart state itself is hoisted on the page and **seeded from the patient's active card services** (same active-set rule the card uses: not cancelled, not fully settled; checkups stay while any line unsettled), so the pill shows real numbers. «Новый визит» buttons in the card header and the patients table now navigate here (inpatient-disabled logic stays).

**Architecture:** Task 1 TDDs `src/domain/visit.ts` — `svcWord` (russian plural of «услуга»), `visitShort` (Первичный→1П), `splitTime`, `needsSchedule`, `normName` (dup-detection normalizer), `slotFrom` (minutes→«09:00–09:20»), `pickAutoDoc`/AUTO_DOCS, `coverageSummary`/`coverageAllocations` (reg-coverage.jsx:8-17) — and ports the reference data into `src/data/visit.ts`: SRV_TYPES/SRV_DIRECTIONS/SRV_SERVICES/SRV_SLOTS(+CLOSED/BOOKED), COVERAGE_TYPES/COVERAGE_PAYERS/PATIENT_POLICIES, REFERRAL_CATEGORIES/REFERRAL_SOURCES/PARTNER_DOCS, APPROVED_DISCOUNTS/SERVICE_PREP/BIO_OPTIONS (used by 4b-4d, ported now — they live in the same prototype data block), LAST_PACKAGE/INIT_PACKAGES, SRC_META/REG_ME. Task 2 builds `features/registration/visit/`: `VisitPage.tsx` (route, subbar, inpatient guard, cart seeding via the existing `svcSettled`/`svcInCart` from `domain/checkup.ts`, settings bar, panel-2 stub «Назначения — следующий этап»), `VisitSettingsBar.tsx`, `CoverageDialog.tsx`, `ReferralDialog.tsx`, `LoyaltyDialog.tsx`, `AttachPatientModal.tsx`. Ported from `reg-visit.jsx` (whole file), `reg-services.jsx:30-72,217-258,675-722` (attach/seeding/guard/shell), `reg-data.jsx:216-326`, `reg-coverage.jsx:8-17`. The picker (4b), the appointments table (4c), and invoice/prints + CoverageEditor/BulkCoverage/CreatePolicy modals (4d) are explicitly NOT in this plan.
